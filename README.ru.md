# OrcaSlicer для ИИ-агентов

[English](README.md) | [Русский](README.ru.md)

Это **неофициальный форк [OrcaSlicer](https://github.com/OrcaSlicer/OrcaSlicer)**, предназначенный для автономной работы ИИ-агента со слайсером: от загрузки модели и настройки поддержек до нарезки, проверки результата и отправки задания выбранному принтеру. Репозиторий форка — [outsid3rx/OrcaSlicer-Agent-control](https://github.com/outsid3rx/OrcaSlicer-Agent-control). Он не является официальным релизом OrcaSlicer и не сопровождается командой upstream.

В одном репозитории находятся изменённый слайсер, универсальный MCP-сервер и навык для агента. Для работы не нужны собственный сервер, аккаунт библиотеки рецептов или отдельное приложение для настроек.

Релизы форка используют версию upstream и ревизию агента, например `2.5.0-dev-agent.1`; MCP сохраняет собственную версию. См. [версионирование и обновление upstream](docs/agent/DISTRIBUTION.ru.md#обновление-из-upstream).

## Зачем нужна отдельная сборка

MCP должен работать с текущим открытым проектом: видеть модели и столы, менять настройки, получать результат нарезки и выбирать устройство. Обычный CLI OrcaSlicer не даёт такого доступа к состоянию работающего GUI. Официальная сборка не содержит используемого здесь AgentControl API; подключение одного MCP-сервера не добавляет этот API в установленное приложение.

Форк добавляет модуль [`src/slic3r/AgentControl`](src/slic3r/AgentControl), который выполняет проверенные операции через собственные механизмы Orca. Он компилируется вместе со слайсером, но **включается только при явном запуске с `ORCA_AGENT_CONTROL=1`**. Обычный запуск оставляет API выключенным. Архитектура и границы доступа описаны в [AgentControl](docs/HLSD/agent-control.ru.md).

## Что умеет агент

- Загружать и сохранять модели и проекты, создавать столы, размещать и преобразовывать объекты.
- Менять настройки процесса, стола, объекта, части и диапазона высоты, включая поддержки, мосты и разглаживание.
- Использовать доступные в текущей сборке операции геометрии и раскраски, выполнять нарезку и получать реальные PNG-превью модели и траекторий.
- Выбирать принтер, получать AMS/внешние катушки, сопоставлять используемые филаменты со слотами и синхронизировать поддерживаемое одиночное сопло.
- Вести локальную библиотеку рецептов: наборы настроек с неизменяемыми редакциями, проверкой совместимости, композицией и JSON-импортом/экспортом.
- Подготавливать задание печати и отправлять его по правилам разрешения владельца, сохраняя квитанцию операции.

Доступность конкретных действий определяется возможностями запущенной сборки, типом принтера и телеметрией. Подтверждённая передача файла не доказывает начало или успех физической печати.

## MCP-сервер

[`mcp/`](mcp) — Python-пакет `orca-slicer-mcp`, использующий официальный MCP SDK и транспорт **stdio**. Он работает с любым клиентом, поддерживающим этот транспорт: например, Codex, Claude Desktop, Cursor, Windsurf или ZCode. Конкретные способы настройки и доступность навыков зависят от клиента. Отдельный HTTP MCP-сервер не запускается: MCP подключается к приватному аутентифицированному API Orca на loopback.

Сервер предоставляет **28 инструментов**. Нативные схемы и возможности текущей сборки доступны агенту; нет инструмента произвольного выполнения кода. При нескольких экземплярах агент выбирает полную пару `session_id` / `window_id`, а не активное окно или первый элемент списка. Изменения привязаны к состоянию проекта, а длительные операции возвращают задания для наблюдения.

Библиотека рецептов хранится отдельно от приложения и checkout, на macOS — в `~/Library/Application Support/orca-slicer-mcp/recipes.sqlite3`. Одну базу могут использовать несколько MCP-клиентов. [Описание MCP](mcp/README.ru.md) · [Контракт рецептов](mcp/docs/contracts/recipes-v1/CONTRACT.ru.md).

## Навык агента

[`skills/orca-mcp-control/SKILL.md`](skills/orca-mcp-control/SKILL.md) объясняет агенту рабочий порядок: выбор окна, проверку возможностей, подготовку модели, сопоставление материалов, проверку нарезки и обработку неопределённых результатов. Навык дополняет MCP инструкциями; он не заменяет сервер и отдельную сборку Orca.

Перед отправкой задания агент показывает время, расход филамента, скриншот нарезки и изменения настроек, затем запрашивает разрешение. По правилам этого навыка дополнительное подтверждение не нужно, если пользователь уже явно разрешил эту печать или имя выбранного принтера содержит `virtual`. Для уже разрешённой или виртуальной отправки тот же отчёт показывается после неё. Имя `virtual` обозначает принятый владельцем сценарий прокси/очереди, но не доказывает, что физическая печать не начнётся. Все нативные проверки и разрешение на работу с устройством сохраняются.

## Установка

Проверенная платформа — **macOS arm64**. Windows/Linux учитываются в исходниках, но сборка и установка этого комплекта на них не подтверждены.

1. Установите сборку OrcaSlicer с AgentControl из релиза этого форка либо соберите её из исходников.
2. Установите [uv](https://docs.astral.sh/uv/getting-started/installation/). Установщик MCP использует его для отдельного окружения Python и не устанавливает `uv` скрыто.
3. Из корня репозитория установите MCP и получите универсальную конфигурацию stdio для своего клиента:

   ```sh
   ./scripts/agent/install.sh install
   ./scripts/agent/install.sh doctor
   ```

4. Запустите Orca с явным включением управления и разрешёнными каталогами моделей/экспорта. Переподключите MCP в клиенте.

Для автоматической настройки Codex и/или ZCode можно дополнительно передать `--client codex --client zcode`; навык будет установлен для выбранных клиентов.

Без `--client` установка настраивает только MCP-сервер и печатает его конфигурацию stdio; навык автоматически не устанавливается. Для других клиентов перенесите включённый в комплект каталог `skills/orca-mcp-control/` по инструкции установки навыков вашего клиента. Если клиент не поддерживает навыки, примените инструкции из `SKILL.md` как руководство проекта.

Установщик использует постоянный абсолютный путь к установленной команде. Папка checkout и её `.venv` клиентам для работы не нужны. Без `--client` он выдаёт универсальную конфигурацию stdio. [Полная инструкция, запуск Orca, обновление и удаление](docs/agent/INSTALL.ru.md) · [Состав комплекта и выпуск](docs/agent/DISTRIBUTION.ru.md).

Раздел [Releases](https://github.com/outsid3rx/OrcaSlicer-Agent-control/releases) относится только к этому форку. Наличие файлов и статус подписания/нотаризации проверяйте в конкретном релизе; этот README не объявляет релиз опубликованным.

## Обновления и данные

В сборках этого форка с `SLIC3R_AGENT_CONTROL=ON` автоматическая проверка обновления приложения через upstream отключена; ручная команда проверки открывает Releases форка. Это изменение требует новой сборки Orca и не появляется в старом приложении при обновлении одного MCP.

Orca, MCP и контракт рецептов имеют независимые версии. Релиз фиксирует совместимый комплект; MCP проверяет API и возможности запущенной Orca. Обновление MCP и удаление его окружения сохраняют библиотеку рецептов, операционные квитанции и данные Orca. JSON-дамп предназначен для обмена рецептами и не заменяет резервную копию SQLite с журналом операций.

Публичная сборка не включает личные сертификаты Bambuddy, токены, локальную базу или пользовательские модели. Пользовательский сертификат, добавленный непосредственно внутрь `.app`, может потеряться при замене приложения. Подробности обновления и доверия сертификатам приведены в [инструкции](docs/agent/INSTALL.ru.md#обновление-и-локальные-данные).

## Сайт проекта

В [`website/`](website/README.ru.md) находится статическая страница с описанием проекта,
FAQ, промптом установки через ИИ и запасной ручной инструкцией. Готовые файлы лежат
в `website/dist/`: английская версия по умолчанию — `index.html`, русская — `ru/index.html`, с переключением языка. Сборка и отдельный backend не нужны.

```sh
python3 -m http.server 8080 --directory website/dist --bind 127.0.0.1
```

Для GitHub Pages выберите **GitHub Actions** в Settings → Pages. Workflow **Agent website** автоматически публикует `website/dist/` после изменения сайта в `main`; ручной запуск также доступен. Остальная часть репозитория не загружается в Pages.

Основной сайт: https://outsid3rx.github.io/OrcaSlicer-Agent-control/.

## Разработка и проверки

```sh
cd mcp
uv sync --locked
uv run --locked python -m unittest discover -s tests -v
uv run --locked python docs/contracts/recipes-v1/verify_contract.py
```

Нативная сборка использует существующий CMake-процесс OrcaSlicer. Параметр `SLIC3R_AGENT_CONTROL=ON` включает модуль при компиляции; переменная окружения `ORCA_AGENT_CONTROL=1` отдельно разрешает его запуск. Обычная CMake-сборка не требует установки MCP. [Архитектура MCP](mcp/docs/architecture.ru.md) · [Запись проверок и их ограничения](mcp/docs/verification.ru.md).
