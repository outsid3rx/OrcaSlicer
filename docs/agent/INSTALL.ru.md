# Установка OrcaSlicer для агента

[English](INSTALL.md) | [Русский](INSTALL.ru.md)

Комплект состоит из отдельной сборки OrcaSlicer с AgentControl, MCP-сервера и навыка. Нативная сборка нужна для работы с открытым проектом; официальный OrcaSlicer не предоставляет используемый этим MCP API. Текущий установщик рассчитан только на macOS; проверенная платформа комплекта — macOS arm64. Документация не подтверждает публикацию релиза, Developer ID или нотариальную проверку: смотрите сведения конкретного файла в [Releases форка](https://github.com/outsid3rx/OrcaSlicer-Agent-control/releases).

## OrcaSlicer

Установите приложение из DMG форка в `/Applications` либо используйте собственную сборку с `SLIC3R_AGENT_CONTROL=ON`. Замену приложения выполняйте при закрытом Orca, предварительно сохранив проекты.

Доступ агента выключен при обычном запуске. Для него запустите бинарник напрямую, указав **существующие абсолютные** каталоги моделей и экспорта:

```sh
ORCA_AGENT_CONTROL=1 \
ORCA_AGENT_INPUT_ROOTS='["/Users/your-name/Models"]' \
ORCA_AGENT_OUTPUT_ROOTS='["/Users/your-name/Exports"]' \
/Applications/OrcaSlicer.app/Contents/MacOS/OrcaSlicer
```

Замените пути на свои; MCP не может расширить эти разрешённые каталоги. Без них операции с файлами отклоняются. Если Orca уже работает без AgentControl, закройте его и запустите заново с нужным окружением: подключение MCP не меняет переменные уже запущенного процесса.

Для отправки заданий и управления устройством дополнительно задайте `ORCA_AGENT_PRINTING=1` в том же окружении запуска Orca. Это разрешает нативный доступ, но не заменяет правила подтверждения конкретного задания. Для нескольких процессов включите настройку нескольких экземпляров Orca. Агент должен выбрать полную пару UUID окна, соответствующую проекту.

## MCP и навык

Установите [uv](https://docs.astral.sh/uv/getting-started/installation/). Скрипт использует установленный `uv` для Python и окружения MCP; он не скачивает сторонний установщик через скрытый `curl`.

Из корня checkout установите MCP и получите универсальную конфигурацию stdio:

```sh
./scripts/agent/install.sh install
```

Добавьте выданную конфигурацию в свой MCP-клиент. Например, Codex, Claude Desktop, Cursor, Windsurf и ZCode могут запускать stdio MCP-серверы; точный формат настройки и поддержка навыков зависят от клиента. Для автоматической настройки Codex и/или ZCode используйте необязательные флаги:

```sh
./scripts/agent/install.sh install --client codex --client zcode
```

`--client` можно указать один раз или несколько. Установщик:

- Устанавливает MCP через `uv tool install` и записывает абсолютный путь команды из `uv tool dir --bin`, обычно `~/.local/bin/orca-slicer-mcp`.
- Изменяет только запись `orca-slicer` выбранного клиента, сохраняет остальные настройки и создаёт соседнюю резервную копию `*.orca-backup-<timestamp>` перед изменением.
- При выборе соответствующего `--client` устанавливает навык в `~/.codex/skills/orca-mcp-control` и/или `~/.zcode/skills/orca-mcp-control`.
- Сохраняет рецепты, квитанции операций, журналы печати, профили Orca и пользовательские сертификаты.

В установочном архиве релиза wheel уже лежит рядом со скриптами: после распаковки та же команда `./scripts/agent/install.sh install` найдёт его автоматически. Предварительно сверяйте архив с `SHA256SUMS` из доверенного релиза.

Для установки отдельно скачанного wheel:

```sh
./scripts/agent/install.sh install \
  --wheel /absolute/path/orca_slicer_mcp-0.4.0-py3-none-any.whl \
  --client codex --client zcode
```

Для предварительного просмотра без записи, установки пакетов и сетевых запросов добавьте `--dry-run`. Такой запуск требует уже доступный Python 3.12: отсутствующий runtime намеренно не скачивается. MCP можно установить и без `--client`: скрипт выдаст универсальную JSON-конфигурацию stdio для ручного добавления в другой клиент.

```sh
./scripts/agent/install.sh install --dry-run --client codex
./scripts/agent/install.sh config --client zcode
./scripts/agent/install.sh doctor
```

`config` настраивает выбранные клиенты на уже установленную команду. `doctor` проверяет запуск MCP, инициализацию протокола и список инструментов; он не вызывает нативные операции и не отправляет данные принтеру. Сам запуск сервера может инициализировать локальную библиотеку рецептов. Успех `doctor` не доказывает, что окно Orca уже включено. После установки или обновления переподключите MCP/перезапустите клиент: запущенный процесс сервера сам не заменится.

Без `--client` установка настраивает только MCP-сервер и печатает его конфигурацию stdio; навык автоматически не устанавливается. Для других клиентов перенесите включённый в комплект каталог `skills/orca-mcp-control/` по инструкции установки навыков вашего клиента. Если клиент не поддерживает навыки, примените инструкции из `SKILL.md` как руководство проекта.

Навык необязателен для протокола MCP, но содержит рабочие правила агента, включая проверку нарезки и разрешение отправки. Его исходник находится в [`skills/orca-mcp-control`](../../skills/orca-mcp-control), отдельно от Python-пакета.

## Другие MCP-клиенты

Любой stdio-клиент может запустить установленную команду. Используйте абсолютный путь, выданный установщиком; имена полей внешнего конфигурационного файла зависят от клиента:

```json
{
  "mcpServers": {
    "orca-slicer": {
      "command": "/Users/your-name/.local/bin/orca-slicer-mcp",
      "args": []
    }
  }
}
```

URL endpoint и auth token не нужны в конфигурации клиента или сообщениях агента. Они читаются из приватных дескрипторов Orca.

Для Orca с собственным `--datadir` добавьте **аргументы MCP** `--directory /absolute/datadir/cache/agent-control`. Для иной общей базы рецептов добавьте `--recipes-db /absolute/private/directory/recipes.sqlite3`; её каталог должен быть приватным. Эти параметры относятся к MCP, а `ORCA_AGENT_CONTROL` и разрешённые каталоги файлов — к процессу Orca.

## Работа и отправка печати

После подключения агент вызывает `orca_list_instances`, выбирает окно по полным `session_id` / `window_id`, затем читает возможности и сцену. При неоднозначности он спрашивает пользователя. Нельзя выбирать окно по фокусу или порядку списка.

Навык требует перед отправкой собрать итоговые данные: принтер и действие, время, расход филамента, реальный скриншот нарезки и отличия от сохранённого пресета. Если пользователь ещё не разрешил печать и имя принтера не содержит `virtual`, агент показывает отчёт, спрашивает разрешение и ждёт ответа. При изначальном разрешении или `virtual` тот же отчёт показывается после отправки.

Устройство с `virtual` в имени обычно используется владельцем для прокси/очереди, например Bambuddy. Это правило навыка снимает только дополнительный запрос разрешения; оно не обходит проверки совместимости, не разрешает незапрошенную печать и не доказывает отсутствие физического запуска. Потерянная квитанция требует наблюдения/сверки исходной операции, а не автоматической повторной отправки.

## Обновление и локальные данные

Обновляйте Orca сборкой **из этого форка**. Официальная upstream-сборка не содержит AgentControl, поэтому замена ею уберёт API, даже если MCP останется установленным. В текущих исходниках сборка с `SLIC3R_AGENT_CONTROL=ON` отключает автоматическую проверку обновления приложения через upstream, а ручная команда проверки открывает Releases форка. Для этого изменения нужно обновить само приложение; установка нового MCP не меняет updater уже установленной старой Orca. Не считайте предложение штатного обновления старой сборки подтверждением совместимости с этим форком.

MCP обновляется из выбранного checkout или проверенного wheel:

```sh
./scripts/agent/install.sh update --client codex --client zcode
```

Клиентам не нужен checkout после установки. Перед запуском работы MCP проверяет протокол и возможности Orca; номер MCP не обязан совпадать с версией приложения. Релиз комплекта указывает совместимые версии и контрольные суммы файлов.

На macOS библиотека рецептов по умолчанию хранится в `~/Library/Application Support/orca-slicer-mcp/recipes.sqlite3`. Обновление/удаление MCP не стирает эту базу или журнал выполненных операций. JSON-дамп используется для обмена рецептами; он не содержит операционные квитанции и не заменяет резервную копию SQLite. Не подменяйте рабочую базу дампом или старой копией при незавершённой операции.

Публичный DMG не содержит личный CA Bambuddy. Храните оригинал пользовательского сертификата отдельно от `.app`. Если сертификат был вручную добавлен в ресурсы приложения, замена `.app` удалит это изменение; текущая инструкция не обещает его автоматический перенос. Добавление доверия должно оставаться явным локальным действием, а отключение TLS-проверки не является заменой сертификату.

Удаление установленного MCP и его записей выбранных клиентов:

```sh
./scripts/agent/install.sh uninstall --client codex --client zcode
```

Команда удаляет общее окружение MCP: клиенты, не выбранные через `--client`, сохранят свои записи, но до повторной установки запускаться они не смогут. Пользовательские данные и резервные копии остаются. Удаление MCP не останавливает задание, уже принятое слайсером или принтером.

## Исходники и проверка

Разработка MCP из корня репозитория:

```sh
cd mcp
uv sync --locked
uv run --locked python -m unittest discover -s tests -v
uv run --locked python docs/contracts/recipes-v1/verify_contract.py
```

Настройки клиентов для обычной установки не должны указывать на эту `.venv`. Нативная архитектура, opt-in и границы доступа описаны в [AgentControl](../HLSD/agent-control.ru.md), проверенные сценарии и ограничения — в [записи проверок MCP](../../mcp/docs/verification.ru.md). Тесты адаптера и успешная нарезка не доказывают физическое качество или безопасность конкретной печати.
