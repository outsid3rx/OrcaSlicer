# Локальное управление агентами

[English](./agent-control.md) | [Русский](./agent-control.ru.md)

Модуль agent-control открывает работающий FFF-редактор локальным клиентам через HTTP JSON-RPC 2.0. Отдельный MCP-адаптер может использовать тот же API, что и обычный клиент на Python, JavaScript или C++. Модуль находится в `src/slic3r/AgentControl/`; он не зависит от вкладки Design/CAD или встроенной среды Python-плагинов.

## Владение и интеграция

`RpcServer` владеет loopback-слушателем и его сетевым рабочим потоком. `Commands` владеет ограниченным синхронизированным реестром копий запросов и результатов заданий. `Controller`, принадлежащий `MainFrame`, обрабатывает эту очередь по таймеру wx. Транспортные обработчики никогда не ждут поток UI и не сохраняют указатели на живую модель/конфигурацию.

`SettingsDomain`, `SceneDomain`, `GeometryDomain`, `DevicesDomain` и `PrintingDomain` владеют схемами и обработчиками своих команд. `Controller` отвечает за проверку цели/состояния, приём команд, защиту операций, асинхронное завершение и отмену. Публичные операции имеют явные имена; произвольного вычислителя Plater, Python или G-code нет.

Изменения настроек строго разбирают отдельную конфигурацию-кандидат и проверяют затронутые эффективные конфигурации нативным `DynamicPrintConfig::validate(true)` перед записью. Фиксация процесса и редактируемого пресета поступает в `Tab::apply_agent_config` полной копией; переопределения модели/стола используют своих нативных владельцев и обновляют UI настроек, не меняя выбор в UI. Одно изменение создаёт один нативный снимок Undo. Изменения остаются несохранёнными, пока клиент явно не попросит сохранить проект или пресет.

Публичный `Plater::slice_current_plate` делегирует тому же действию текущего стола, что использует UI, включая подготовку к нарезке и предупреждения. `BackgroundSlicingProcess` назначает каждому успешному запуску монотонно возрастающий ID. События прогресса и завершения несут этот ID, поэтому поставленное в очередь событие другого запуска не может завершить задание агента. Оценки поступают из нативного `GCodeProcessorResult`.

Небольшие вызовы `Hooks.hpp` связывают изменения документа/конфигурации, нарезку и сериализацию с модулем. При отключении функции во время компиляции hooks ничего не делают. Защита операций охватывает импорт/сброс/экспорт проекта, создание снимков, undo/redo и распространение конфигурации; таймер не входит в эти критические секции из вложенного цикла событий. Запросы закрытия и пересоздания GUI откладываются, пока выполняемая команда или сериализация не покинет стек. Завершение работы прекращает приём, оставляет невыполненной очередь, закрывает сокеты, присоединяет сетевой поток и удаляет файл обнаружения окна до уничтожения Plater.

## Включение и обнаружение

`SLIC3R_AGENT_CONTROL` управляет компиляцией и по умолчанию равен ON. Слушатель выключен, пока процесс не запущен с `ORCA_AGENT_CONTROL=1`. Например, специальную сборку macOS запускают напрямую:

```sh
ORCA_AGENT_CONTROL=1 /path/to/OrcaSlicer.app/Contents/MacOS/OrcaSlicer
```

При открытии нескольких окон используйте существующую настройку Orca, разрешающую несколько экземпляров приложения. Каждый включённый MainFrame получает отдельную конечную точку и приватный дескриптор:

```text
<Orca data_dir>/cache/agent-control/<session_id>-<window_id>.json
```

Дескриптор содержит версию протокола, конечную точку, PID, ID сессии/окна и секретный токен аутентификации. Файлы/каталоги POSIX доступны только владельцу; файлы Windows имеют защищённый ACL текущего пользователя. Публикация атомарна и не перезаписывает существующий дескриптор. Завершившийся владелец удаляет только собственный файл. Клиенты игнорируют устаревшие дескрипторы после неуспешных аутентифицированных проб; никогда не выбирают по PID, порту или имени проекта и не удаляют файлы по тайм-ауту пробы.

| Идентификатор | Срок жизни |
|---|---|
| `session_id` | Случайный UUID v4 процесса; сохраняется при пересоздании GUI |
| `window_id` | Случайный UUID v4 MainFrame; заменяется при пересоздании GUI |
| `document_epoch` | Меняется при сбросе документа или импорте файлов |
| `auth_token` | Случайный секрет слушателя на 256 бит; независим от ID |

Существующий хеш экземпляра по пути исполняемого файла и постоянный UUID updater/machine имеют другие сроки жизни и не используются как эти ID времени выполнения.

## Протокол обмена

Отправляйте `POST /api/v1/rpc` по адресу дескриптора `http://127.0.0.1:<port>` с `Authorization: Bearer <auth_token>` и `Content-Type: application/json`. Host должен точно совпадать с loopback-конечной точкой. Browser Origins, перенаправления, публичные/LAN-привязки и произвольное выполнение кода не входят в API. Передача на принтер и управление устройством требуют отдельного включения владельцем, описанного ниже. Сроки заголовка/тела, ограничения соединений и запросов, запрет повторяющихся ключей и глубина JSON проверяются до приёма команды. Тело HTTP ограничено 1 MiB; приём команд применяет меньший лимит сериализованного JSON, указанный ниже.

Первый `system.describe` может не содержать target. Каждый другой запрос должен включать точную пару, полученную при обнаружении:

```json
{
  "jsonrpc": "2.0",
  "id": "client-unique-request-id",
  "method": "scene.describe",
  "params": {
    "target": {
      "session_id": "<full-session-uuid>",
      "window_id": "<full-window-uuid>"
    }
  }
}
```

Все принятые команды, кроме `jobs.get`, немедленно возвращают `result.job_id` и `result.target`. Опрашивайте `jobs.get` с той же целью и `job_id`; он возвращает `state` задания и, после завершения, `result` или `error`. Тайм-аут клиента не означает ошибку команды: сохраните ID задания и опросите снова. Если ответ о приёме потерян, повторите точную оболочку с тем же ID запроса. Повторное использование сохранённого ID для другого содержимого отклоняется.

Реестр хранит до 256 заданий, вытесняя только завершённые записи. Приём ограничивает сериализованный запрос 64 KiB, а хранимые копии запросов — 4 MiB (разобранное представление JSON имеет дополнительные накладные расходы аллокатора). Полный сериализованный статус одного задания ограничен 3 MiB, а все хранимые статусы/результаты делят бюджет 16 MiB. При нехватке места вытесняются только завершённые задания; одновременно освобождаются их записи ID запросов и копии запросов. Выполняемая работа сохраняется. Превышение лимита результата оставляет небольшую квитанцию ошибки `result_too_large` с `operation_may_have_completed: true`; это не откатывает выполненную операцию и не разрешает новое изменение. Текст прогресса ограничен 4 KiB без разрыва кодовых точек UTF-8. Команда в очереди истекает через 15 секунд и после этого никогда не выполняется. Повторно предъявленные старые изменения всё ещё должны соответствовать исходному токену состояния даже после вытеснения истории заданий. Запросы отмены приоритетнее их целей в очереди. Запущенное короткое изменение нельзя откатить отменой запроса; отмена активной нарезки разрешена только пока её нативный ID запуска принадлежит модулю.

Состояния заданий: `queued`, `running`, `succeeded`, `failed`, `cancelled`. Нативный модальный выбор оставляет задание работающим с `waiting_for_user: true`; API никогда не выбирает за пользователя Discard, Transfer или ответ на предупреждение. Отклонённые операции сообщают структурированные виды ошибок, например `busy`, `conflict`, `stale_target`, `invalid_scope`, `invalid_value`, `invalid_config`, `slice_not_started` и `superseded`. Завершение основано на реальном нативном событии, а не тайм-ауте.

| Метод | Параметры кроме target | Результат внутри завершённого задания |
|---|---|---|
| `system.describe` | Нет | Версии API/приложения, ID цели, возможности, JSON-схемы параметров |
| `scene.describe` | Необязательные `offset`, `limit` | Подпись проекта/окна, идентичность документа, столы, объекты, экземпляры, части и токен состояния |
| `settings.describe` | Необязательные `scope`, `filter`, `keys`, `offset`, `limit` | Нативные доступные для записи ключи, типы/диапазоны/перечисления и разрешённые области |
| `settings.get` | `scope` и явный владелец модели/стола, необязательная страница/фильтр | Эффективные/собственные значения, наследование, имя пресета и токен состояния |
| `settings.patch` | Явные `scope`, `state_token`, `values` и/или `unset`, ID владельцев | Фактические значения, изменённые ключи и новый токен состояния |
| `slicing.start` | `state_token`, явный текущий `plate_index` | Оценки и диагностика после завершения нативного запуска |
| `slicing.result` | `job_id` завершённой нарезки | Результат, если текущие входные данные всё ещё соответствуют ему |
| `slicing.start_many` | `state_token`, явные `plate_ids` | Квитанция родительского пакета и реальные ID дочерних заданий нарезки; частичный сбой сохраняет дочерние квитанции |
| `jobs.cancel` | ID целевого задания | Подтверждение отмены |
| `jobs.get` | ID задания | Немедленный статус; дополнительное задание не создаётся |

`scope` — `process`, `plate`, `object`, `volume` или `height_range`. Запись процесса влияет на активный редактируемый пресет процесса. Запись модели требует объекта с экземпляром на явном столе. Старые вызовы процесса/объекта без стола используют текущий стол. Предпочтителен канонический `plate_id`; необязательный `plate_index` должен ему соответствовать. Изменения объекта, части и диапазона высот затрагивают все связанные экземпляры, включая другие столы. Каждая затронутая цепочка наследования проверяется перед фиксацией. `unset` удаляет переопределения; значения процесса удалить нельзя. `own_value` может быть null, тогда как `value`, `source` и `inheritance` описывают эффективное значение. Значения используют сериализацию Orca, например:

```json
{
  "scope": "object",
  "object_id": "<ID-from-scene>",
  "state_token": "<token-from-settings-or-scene>",
  "values": {"wall_loops": "4", "sparse_infill_density": "30%"}
}
```

Доступные для записи настройки процесса выводятся из `Preset::print_options` и охватывают обычные поддержки, мосты, нависания, скорости, ускорения, ширины, массивы, булевы значения и перечисления. Исполняемый код, шаблоны G-code, сетевые учётные данные, плагины, идентичность бэкенда, пути внешних ресурсов стола и внутренний учёт пресетов/инструментов исключены. `settings.describe` авторитетен. Страницы схемы/значений принимают чувствительный к регистру фильтр имени/категории/подписи, точные ключи, смещение и лимит 1–100 (по умолчанию 80). Исходные пятнадцать ключей также включаются в первое нефильтрованное чтение процесса/объекта для существующих клиентов v1.

Ключи стола происходят из нативной вкладки стола; произвольные параметры поддержек не являются переопределениями стола. Ключи объекта объединяют нативные PrintObjectConfig и PrintRegionConfig. Части/модификаторы принимают только PrintRegionConfig. Диапазоны высот используют `[lower, upper)` в миллиметрах и принимают высоту слоя плюс настройки региона. Изменение может создать непересекающийся диапазон с нативным наследованием `extruder=0` и эффективной высотой слоя; ни одно обязательное поле диапазона удалить нельзя. Экземпляры не владеют независимыми настройками печати. Переопределения материала модели, если есть, остаются в нативной цепочке наследования и сообщаются при чтении части. Индексы назначения материалов должны указывать существующие слоты филамента от 1 либо ноль для наследования.

`presets.list/describe/select/patch/save_as` поддерживают коллекции процесса, филамента и машины. Выбор сохраняет нативные решения Transfer/Discard/Save и проверяет видимость/совместимость. Patch изменяет управляемую копию, а не JSON на диске, сохраняя размеры векторов. Изменение филамента сейчас требует одного слота. Save-as проверяет простое новое имя и использует нативное сохранение только с созданием: сначала сериализует, атомарно публикует без замены, затем регистрирует/выбирает новый пресет. Существующие имена реестра, файловые псевдонимы и коллизии sidecar отклоняются; неудачная публикация не создаёт фиктивный зарегистрированный пресет. POSIX использует новую жёсткую ссылку, Windows — перемещение без замены. Обычный путь сохранения GUI сохраняет прежнюю семантику перезаписи. Запись sync sidecar сохраняет нативный режим best-effort с публикацией только с созданием для этого API.

Входной токен хеширует текущие конфигурации, идентичность пресетов, входные конфигурации столов, конфигурации материалов модели и идентичности объёмов, данные сетки, преобразования, переопределения/профили слоёв и временные метки раскраски граней вместе с эпохами владельцев. Он выявляет ручные изменения и Undo, а не просто считает удалённые запросы. Автоматически разрешённые сопоставления филамента стола, сопла и объёмов — производные результаты в соответствующих автоматических режимах; ручные назначения остаются хешируемыми входами. Нативный поток нарезки записывает эти результаты через учитывающий отмену мост GUI-задач, чтобы чтение не конкурировало с изменением карты параметров. Хеширование больших сеток может занимать время UI; клиентам следует опрашивать задания, а не многократно запрашивать полные сцены.

Изменение входов лишает активное задание права на результат; модуль не отменяет заменяющую нарезку, запущенную пользователем. Результаты включают нативное время normal mode в секундах, объём филамента в mm³, индекс стола, входной токен и нативную диагностику. Оценки — прогнозы слайсера, а не измеренные физические результаты печати.

## Сцена, файлы и редактирование модели

`scene.describe` предоставляет явные идентичности документа, стола, объекта, экземпляра и объёма, преобразования, габариты, принадлежность и ревизии сетки. Идентификатор стола включает эпоху документа и нативную идентичность печати; это не постоянный ID 3MF и не изменяемый индекс списка. Изменения сцены и нативная история могут сделать идентификаторы недействительными. Повторно прочитайте сцену после изменения, запрашивающего обновление. `mesh_revision` хеширует идентичность объёма, исходные вершины/треугольники и его локальное преобразование. ID граней адресуют исходные треугольники сетки, а не созданные подразделения.

Домен сцены предоставляет создание/выбор/переименование/дублирование/порядок/блокировку столов, удаление пустых незаблокированных столов, явные преобразования экземпляров, центрирование/опускание, отражение, ориентацию на грань, флаги участия в печати, клонирование/удаление/перемещение на стол и нативную расстановку. Расстояния — в миллиметрах, вращения — в градусах, масштаб — положительный коэффициент. Каждое преобразование задаёт поддерживаемую систему координат; объявленная схема отклоняет неподдерживаемые сочетания абсолютных/относительных параметров. Действуют нативные ограничения связанных экземпляров: общая геометрия, наклон XY, масштаб и отражение не становятся независимо редактируемыми только из-за адресации экземпляра. При необходимости `objects.make_independent` создаёт независимого владельца модели.

Команды объектов/частей переименовывают, клонируют, удаляют, разделяют несвязанные оболочки на объекты или части, группируют совместимые объекты в составной объект и добавляют/удаляют/меняют тип примитивных отрицательных объёмов, модификаторов параметров и принудительных/запрещающих поддержек. Группировка не является булевым объединением. Объединение в составной объект требует объектов на одном столе, с одним экземпляром, одинаковыми переопределениями объекта и без диапазонов высот. Результаты указывают созданные/удалённые/заменённые сущности вместо сохранения устаревших ID.

Файлы требуют заданных владельцем переменных окружения `ORCA_AGENT_INPUT_ROOTS` и `ORCA_AGENT_OUTPUT_ROOTS` в виде JSON-массивов. Проверки происходят в нативной конечной точке, а не только в MCP. Пути — абсолютные локальные; API не загружает URL. `InputSnapshot` проверяет открытый обычный файл, его фактический разрешённый путь, размер и метаданные изменений, затем хеширует приватный снимок перед нативным разбором. `OutputArtifact` готовит полный результат и атомарно публикует через проверенный выходной каталог; существующий файл требует явного `overwrite`. Символические ссылки в назначении отклоняются. Нативный Undo документа не отменяет внешние файловые записи.

`model.import` принимает STL, OBJ, 3MF только с геометрией, AMF и STEP/STP. В пакете максимум 16 источников и 256 MiB суммарно; каждый источник подготавливается до фиксации модели. Импортированные пресеты печати/сети и переопределения исключены. Нативный разбор сейчас работает в GUI-потоке, поэтому большой импорт может приостановить UI. `project.open` явно требует `load_config: true` и сохраняет нативные диалоги несохранённого проекта/пресета; если нужна только геометрия, используйте импорт модели. `project.save` записывает полную копию 3MF, не меняя текущее имя файла проекта и не отмечая состояние редактора как сохранённое. `model.export` записывает бинарный STL или 3MF только с геометрией. `gcode.export` копирует уже действительную траекторию стола и не запускает скрипты постобработки. Проект может содержать настроенное исполняемое содержимое; обычные API настроек не добавляют скрипты, а подготовка печати отклоняет настроенные скрипты постобработки.

## Геометрия, раскраска и визуальная проверка

`geometry.validate`, `geometry.cut`, `geometry.boolean`, `geometry.simplify` и `geometry.repair` используют нативные алгоритмы на отделённых данных модели. Рабочий поток фиксирует результат в GUI-потоке, только если исходное состояние, идентичности объекта/экземпляра и ревизии сетки всё ещё совпадают. Отменённое или конфликтующее вычисление не заменяет живую модель. Успешное логическое изменение использует один нативный снимок Undo. Существующие соответствия разреза/соединители и связанные экземпляры на заблокированных столах накладывают нативные ограничения редактирования; неподдерживаемые случаи отклоняются вместо частичного изменения.

Разрез получает явный экземпляр и плоскость в мировых координатах, выбранные половины и необязательные нативные соединители plug/dowel/snap; соединители требуют двух отдельно сохранённых половин. Булева операция действует на две положительные части одного объекта. Упрощение использует целевое число треугольников и нативную квадратичную метрику ошибки, а не заявленный допуск в миллиметрах. `preview` вычисляет метрики геометрии без фиксации; это не изображение предлагаемого результата. Исправление и замена имеют явную политику сохранения раскраски. Можно проверить нативную корректность сетки, топологию, открытые рёбра, габариты и знаковый объём; это не доказывает физическую посадку или прочность печати.

`preview.render` создаёт нативный OpenGL PNG стола или всей сцены, привязанный к возвращённому токену состояния. Поддерживаемые ортографические виды: изометрия, сверху, спереди, слева и справа; размеры 64–1024 пикселя (по умолчанию 512). Сжатое изображение ограничено 2 MiB и возвращается как `mime_type`, base64 `data`, ширина и высота. Миниатюра стола может не включать объёмы вне стола, непечатаемые объёмы и модификаторы; также изучайте метаданные расположения сцены. Невозможность получить нативный GL-контекст сообщается, а не подменяется выдуманным видом. MCP может показать PNG как изображение.

`painting.describe/clear/set/raycast/brush` адресуют один положительный объём модели и аннотации поддержек, шва или материала. Изменения и raycast требуют исходной `mesh_revision`. Состояния поддержек/шва: automatic/enforce/block; материалы — без раскраски либо существующий слот филамента от 1. Явное изменение грани заменяет всю исходную грань, включая прежние подразделения. Выбор области использует центроиды исходных треугольников внутри включительного AABB в координатах сетки объёма. Raycast и нативные сферические/круговые кисти используют явно переданные лучи в координатах сетки, а не ввод мыши GUI. Мазки кисти сейчас не подразделяют треугольники. Лимит объёма — 500 000 исходных треугольников; явные наборы граней/областей ограничены 10 000 треугольниками на изменение. Обновления аннотаций сохраняют расположение модели и используют нативную инвалидацию сцены/фона и Undo. Описанные нативные строки аннотаций могут сохранять информацию о подразделении, хотя изменение целой грани её заменяет.

`history.describe/undo/redo` используют нативную историю документа. Запись требует доступной истории редактора Prepare и исходного токена состояния. Восстановление должно действительно переместить временную метку нативного основного стека; успех возвращает `refresh_scene` и делает идентификаторы документа недействительными. История не отменяет экспортированные файлы, загруженные файлы или физические эффекты принтера.

## Печать и управление устройствами

Операции принтера явно адресуются через `backend_id` и `device_id`. Имена, фокус UI и активный выбор принтера не выбирают назначение. `printers.list/describe/status` сообщают доступные нативные бэкенды и возможности, не раскрывая коды доступа или приватные адреса. Отправка BBL LAN сейчас запускает проверенный путь с одним соплом и одним филаментом, с нативными проверками загруженного материала/сопла/AMS и хранилища. Загрузки BBL только в хранилище могут направляться в виртуальную очередь без этой телеметрии; непроверенная или несовместимая телеметрия становится явным предупреждением, требующим подтверждения, а проверки транспорта и нарезки обязательны. Параметры запуска не применяются к операциям только загрузки. Настроенный обычный PrintHost поддерживает только явную загрузку; он не заявляет проверенную телеметрию модели/сопла/материала и не открывает действие загрузки с запуском через этот контракт. Облачная отправка и непроверенные сопоставления нескольких экструдеров/материалов не объявлены поддерживаемыми.

`printing.prepare` фиксирует действительную нативную нарезку в приватный артефакт и план на десять минут, не обращаясь к принтеру и не загружая пробный файл. Нужен неизменившийся входной токен; план связывает идентичность окна/документа/стола/нарезки, хеш и размер артефакта, бэкенд/устройство/транспорт, снимок материала/сопла/параметров, действие и ID предупреждений. Сохраняется до 64 планов. Скрипты постобработки отклоняются, а не исполняются неявно при упаковке.

`printing.submit` дополнительно требует, чтобы владелец запустил Orca с `ORCA_AGENT_PRINTING=1`. Нужно разрешить точные ID предупреждений плана. Нативный код повторно проверяет план, исходную нарезку, зафиксированный артефакт, целевые учётные данные/параметры и поколение бэкенда/библиотеки. Бэкенд/библиотека удерживаются для принадлежащего операции рабочего потока; выбор UI не может перенаправить принятый план. Долговечная заявка расходует план до одной передачи. Автоматического перехода LAN→cloud или повтора возможно отправленной команды нет. Отрицательный код транспорта или отмена после заявки оставляют неопределённый результат, а не повторно используемый план.

`PrintJournal` приватен для текущего пользователя и независим от ограниченной истории заданий/файлов обнаружения. Атомарные заявки только с созданием не дают конкурентным процессам дважды израсходовать одну операцию, в том числе после перезапуска. Каталоги журнала и артефактов по умолчанию находятся в кеше пользовательских данных приложения платформы; `ORCA_AGENT_PRINT_JOURNAL` и `ORCA_AGENT_PRINT_ARTIFACTS` переопределяют их. Все клиенты, управляющие одной историей намерений пользователя, должны использовать один каталог журнала, даже если процессы Orca используют разные каталоги данных проекта/обнаружения. Не удаляйте долговечные заявки ради повтора неизвестного результата.

`printing.status/reconcile` различают загрузку, принятие задания и неизвестный результат. Завершение отправки не доказывает физическую печать. При наличии удалённой квитанции сверка может сравнить её точный ID с телеметрией конечной точки; API не выводит совпадение из имён файлов или другого занятого задания. Физический запуск остаётся неподтверждённым, если транспорт не предоставляет достаточной квитанции.

Конечные точки Bambuddy могут маршрутизировать или ставить в очередь дальнейшую работу, в том числе после операции только загрузки. `endpoint_mode` фиксирует явный контекст direct/queue/unknown; он не доказывает конечное физическое назначение. Имя вроде «P1S Virtual» не является проверкой конечной точки. Неизвестная маршрутизация и нативные предупреждения остаются явными в плане и не должны превращаться в обещание, что загрузка не имеет физического эффекта.

`printers.control` сейчас предоставляет явно действующие на всё устройство BBL LAN pause/resume/stop с долговечным UUID операции. Команда может повлиять на любое задание, которое конечная точка выполняет сейчас; атомарное управление в пределах конкретного задания не объявлено. Отмена локального потока отправки или ожидающего клиента не останавливает уже начатую физическую печать. Нативные диалоги предупреждения/сохранения требуют решения пользователя; переданное моделью булево подтверждение не является механизмом авторизации.

## Клиент командной строки

`scripts/agent_control.py` использует стандартную библиотеку Python. Он перечисляет аутентифицированные включённые окна, не печатая токены, требует явных полных ID сессии/окна для вызовов и проверяет соответствие ответов этой цели. Прокси и перенаправления отключены. Для нестандартного каталога данных Orca используйте `--directory`.

```sh
python3 scripts/agent_control.py list
python3 scripts/agent_control.py call --session <uuid> --window <uuid> scene.describe
python3 scripts/agent_control.py call --session <uuid> --window <uuid> settings.patch --params patch.json
python3 scripts/agent_control.py wait --session <uuid> --window <uuid> <job-id>
```

`patch.json` содержит параметры выше; клиент добавляет `target`. Вызовы по умолчанию ждут до 30 секунд и печатают ID/статус задания, если оно ещё активно. Возобновляйте наблюдение через `wait`, а не отправляйте новое изменение. CLI не запускает и не изменяет слайсер, пока явно не запрошен вызов метода.

## Проверка

Изолированные тесты Catch2 в `tests/agent_control` проверяют реальные loopback-сокеты, аутентификацию, отдельные учётные данные/дескрипторы окон, ограниченный приём, тайм-ауты клиента, ротацию токенов, завершение работы, отмену в очереди, дедупликацию запросов, байтовые лимиты сохранённых результатов и структурированные квитанции сбоев. Нативные тесты libslic3r дополнительно покрывают публикацию пресетов только с созданием, неизменность существующих файлов и символических ссылок и состояние коллекции после неудачной публикации. Они входят в обычную сборку тестов и могут работать без библиотек GUI:

```sh
cmake -S tests/agent_control -B build/agent-control -DCMAKE_BUILD_TYPE=Release
cmake --build build/agent-control --config Release
ctest --test-dir build/agent-control -C Release --output-on-failure
```

Автономной сборке нужны заголовки Boost, файлы разработки OpenSSL и компилятор C++17; Catch2 и nlohmann JSON включены в репозиторий. Нативные smoke-проверки GUI также должны проверять два окна, два объекта, чтение/изменение/undo, конфликты ручного редактирования, завершение/отмену нарезки, конкуренцию экспорта, закрытие окна и пересоздание языка/GUI. Проверки компилятора и транспортные тесты не заменяют эти запуски.

## Выбор устройства и материалы

`printers.select` выбирает явное устройство активного бэкенда через нативный путь выбора вкладки Device. Выбор общий для окон процесса; планы печати всё равно привязывают явный бэкенд/устройство, а не выбор UI. Синхронизация сопла по умолчанию включена и асинхронно ждёт телеметрию подключённого устройства. `printers.sync_nozzle` повторяет синхронизацию для того же выбранного устройства. Автоматический путь поддерживает одно установленное сопло без стойки, требует соответствующего профиля принтера и использует нативную синхронизацию боковой панели. Он отклоняет неизвестные компоновки и смену профиля, которая отбросила бы изменённые пресеты. Успешный выбор с заблокированной синхронизацией возвращает `nozzle_sync.state` `blocked` и причину; клиент обязан проверить это до нарезки. Ожидающие задания отслеживают изменения документа/бэкенда/выбора и отменяются без отмены выбора.

`printers.filaments` читает сообщённые блоки AMS, слоты, внешние катушки и телеметрию сопел, не заменяя материалы проекта. Глобальные индексы лотков поступают из `DevFilaSystem::GetTrayIndexMap`, включая нестандартные компоновки AMS.

Предпроверка LAN-запуска проверяет фактический расход филаментов завершённой нарезки, включая поддержки, раскраску и башню, а не число настроенных материалов проекта. Каждый использованный материал проверяется по твёрдости сопла, типу загруженного материала и нативным правилам совместимости. Явный `ams_mapping` содержит по одной записи на использованный ID филамента проекта от 1 и его нативный индекс лотка. `ams_tray_index` остаётся допустимым ровно для одного использованного материала. Массивы полезной нагрузки сохраняют неиспользуемые позиции проекта, сохраняя разреженные ID инструментов артефакта. Поддерживается многоцветная AMS-печать с одним соплом; запуск с двумя соплами/стойкой и ручная многоцветная смена катушек недоступны. При отправке планы повторно проверяют сопоставление материалов и снимок устройства. Успешная передача не подтверждает физическую печать.

## Изображения и отчёты для проверки

`preview.render` сохраняет миниатюры модели стола/сцены и добавляет `scope: slice` для действительных завершённых траекторий выбранного текущего стола. `scope: bed` использует нативную верхнюю камеру стола и накладывает прозрачные пиксели модели на фактический полигон стола с сеткой 10 мм для проверки расположения. Отдельные просмотрщик libvgcode и камера рисуют во внеэкранный framebuffer, сохраняя камеру, фильтры и состояние GL редактора. Вывод содержит идентичность нарезки/состояния и никогда не подменяет недоступную нарезку изображением модели. Ограниченный путь поддерживает до двух миллионов движений и PNG до 1024 пикселей и 2 MiB; используются машинные координаты.

Квитанции завершённой нарезки включают нативное время и расход каждого материала; масса/длина выводятся из метаданных плотности/диаметра результата, когда они известны. `printing.prepare` включает те же оценки плюс отличия от сохранённых выбранных пресетов и явные переопределения стола/объекта/объёма/диапазона высот. Элементы управления проектом используют отдельно обозначенную нативную базу значений по умолчанию. Отчёты исключают исполняемые поля/учётные данные, отмечают усечение и привязывают данные к зафиксированной нарезке. База сравнения — сохранённый пользовательский пресет, а не выдуманный универсальный заводской стандарт.
