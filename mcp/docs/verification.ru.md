# Журнал проверок

[English](./verification.md) | [Русский](./verification.ru.md)

Проверено 2026-10-25 на macOS arm64, Python 3.12.13 и MCP SDK 1.30.0. Адаптер 0.4.0; OrcaSlicer 2.5.0-dev, протокол v1 / ревизия API 3. Это запись результатов указанных проверок, а не утверждение о повторном запуске при переводе документации.

- Прошли 87 тестов адаптера, включая официальный MCP stdio с независимо аутентифицированными окнами, правила повтора/конфликта/отмены, преобразование изображений, неопределённые результаты печати и маршрутизацию/аннотации выбора принтера.
- Прошли пять нативных наборов AgentControl CTest: команды, loopback-транспорт, долговечный журнал печати, доступ к фактически открытым файлам и сопоставление материалов печати. Тесты материалов содержат 28 утверждений, покрывающих разреженные ID проекта, ключи карты с нулевым расходом, точное покрытие сопоставления, неиспользуемые записи, специальные значения внешней катушки и нативные массивы полезной нагрузки сопоставления.
- Приложение собрано в Release. Изменённые/новые файлы модуля прошли clang-tidy репозитория без PCH. Проверки пробельных ошибок diff прошли.
- Изолированные проверки реального GUI/MCP подтвердили отклонение предпросмотра нарезки до нарезки, предпросмотр модели, расположение на полигоне стола с сеткой 10 мм, PNG реальных траекторий G-code, сохранение состояния, нативное время/граммы/метры и отчёты настроек зафиксированного плана. Отчёты проверили отличия от сохранённого процесса и переопределений объекта. Файлы не отправлялись.
- Подписанный автономный bundle повторил сценарий отчёта/предпросмотра. Его 70 файлов Mach-O не имеют внешних несистемных библиотечных зависимостей. Единственная символическая ссылка времени выполнения указывает внутрь bundle. Сертификаты соответствуют upstream и не содержат личный CA Bambuddy; глубокая строгая проверка подписи прошла.
- Изолированный локальный симулятор Moonraker подтвердил явный выбор устройства и идентичность инвентаря. Отсутствующая телеметрия сопла даёт ограниченный по времени результат неготовности и сохраняет выбранное устройство без модального диалога или загрузки.
- Настроенные команды Codex и ZCode инициализируются и предоставляют по 28 MCP-инструментов. Навык рабочего процесса прошёл валидацию и установлен для обоих клиентов. Существующим клиентам нужны новые сессии, чтобы перезагрузить работающий сервер/каталог навыков.

Более ранние проверки ревизии 2 также покрывали широкий набор операций редактирования/геометрии/пресетов, реальные загрузки на локальный тестовый приёмник, предотвращение повторной отправки и потерю ответа после принятия. Это контекст регрессии, а не новые физические доказательства.

Передача на реальный принтер и физическая печать/управление не выполнялись. Эти проверки не подтверждают автоматическую синхронизацию сопла по телеметрии настоящего принтера, реальную многоцветную отправку AMS, облачный запуск, сборку/выполнение Windows/Linux и notarization. Запуск поддерживает одно установленное сопло без стойки сопел и явное сопоставление AMS; запуск с двумя соплами/стойкой и ручная многоцветная смена катушек недоступны. Нативные правила модели/сопла/материала и долговечная повторная проверка отправки сохраняются. Успешная передача файла не подтверждает физическую печать.

Проверка рецептов 0.4.0: прошли 34 переносимые проверки контракта. Тесты SQLite покрывают неизменяемые ревизии, CAS-указатели актуальных ревизий, атомарный импорт, приватное хранилище, конкурентные заявки, восстановление после перезапуска и сохранение резервных копий. Тесты официального MCP stdio покрывают общих клиентов, пагинацию/композицию 106 ключей, конфликты, импорт/экспорт и потерю нативного ответа о приёме без повторной отправки. Тесты числового чтения обратно покрывают строгую нормализацию скаляров без принятия округления или префиксов парсера.

Изолированный подписанный GUI Orca применил два рецепта (число периметров и две настройки поддержек) к одному объекту одним изменением, подтвердил завершение и повторно предъявил план с новым ID запроса без изменения токена состояния. Обращений к принтеру не было. Собранный wheel инициализируется в отдельном окружении со своей схемой; настроенные команды Codex/ZCode предоставляют все 28 инструментов и используют одну библиотеку. Код ACL/блокировок Windows и выполнение Linux не запускались; правил семантической миграции будущих изменений настроек в v1 нет.

## Распространение из единого репозитория

Исходники адаптера находятся в `mcp/`, единственный источник навыка — `skills/orca-mcp-control/` в корне форка. Пользовательская установка использует исполняемый файл uv tool, а не `.venv` рабочего дерева. Это изменение структуры не расширяет приведённые выше утверждения о физическом поведении или выполнении.

У помощника установки macOS есть автономные тесты сохранения конфигурации, резервных копий, установки навыка, dry-run, удаления с сохранением данных и проверки протокола MCP на фикстуре. Doctor проверяет только stdio-инициализацию и схемы инструментов; запуск MCP может создать локальную библиотеку. Он не проверяет доступность Orca/нативного API, телеметрию принтера или физическую печать. Публикация публичного релиза и notarization требуют отдельных доказательств.

Проверки распространения на macOS arm64: прошли все 87 MCP-тестов, 22 теста границ установщика/релиза, 34 переносимые проверки контракта и проверка синтаксиса shell. Изменённое нативное приложение успешно пересобралось. Подготовленный DMG прошёл проверку, содержит CA bundle репозитория, имеет 70 Mach-O без внешних зависимостей времени выполнения и прошёл глубокую строгую проверку ad-hoc-подписи. Developer ID notarization не подтверждена. Установленное приложение и добавленный пользователем CA не заменялись.

Установщик был выполнен для реальных конфигураций Codex и ZCode: посторонние разобранные настройки идентичны, резервные копии существуют, оба используют постоянную пользовательскую команду и инициализируются с 28 инструментами. Установленный wheel также управляет изолированным окном новой сборки Orca, применяет три ключа рецепта и повторно использует тот же план без второго изменения состояния. Обращений к принтеру не было. YAML рабочего процесса разобран локально; GitHub Actions/создание черновика релиза не запускались.
