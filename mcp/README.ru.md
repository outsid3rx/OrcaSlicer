# OrcaSlicer MCP

[English](./README.md) | [Русский](./README.ru.md)

Универсальный локальный stdio-адаптер для специального API управления OrcaSlicer агентами. Использует официальный Python MCP SDK, Python 3.11+ и не зависит от рабочего дерева форка во время выполнения. Не открывает HTTP-слушатель. Работает с любым MCP-клиентом, поддерживающим stdio.

## Установка и подключение

Пакет находится в [форке OrcaSlicer с agent-control](../README.ru.md) рядом с нативным API и навыком рабочего процесса. Требуется совместимая специальная сборка Orca: официальное приложение этого API не содержит.

Из корня репозитория установите пакет в постоянное пользовательское окружение uv tool:

```sh
./scripts/agent/install.sh install
./scripts/agent/install.sh doctor
```

Требуется установленный [uv](https://docs.astral.sh/uv/getting-started/installation/). По умолчанию команда устанавливает MCP-сервер и выводит универсальную конфигурацию stdio для любого совместимого MCP-клиента. Навык рабочего процесса в каталог клиента при этом не устанавливается. Для автоматической настройки поддерживаемых клиентов и установки навыка добавьте `--client codex`, `--client zcode` или оба параметра. Для остальных клиентов перенесите поставляемый навык или инструкции рабочего процесса согласно документации клиента. Английский `SKILL.md` остаётся единственным авторитетным источником навыка. Для установки релизного wheel используйте `--wheel /absolute/path/package.whl`. Во время выполнения рабочее дерево не требуется. См. [инструкции по установке и обновлению](../docs/agent/INSTALL.ru.md) и [распространению](../docs/agent/DISTRIBUTION.ru.md).

Универсальная конфигурация MCP (используйте абсолютный путь установленной команды, указанный установщиком):

```json
{
  "mcpServers": {
    "orca-slicer": {
      "command": "/Users/your-name/.local/bin/orca-slicer-mcp",
      "args": []
    }
  }
}
```

Только для разработки: выполните `cd mcp` из корня репозитория, затем `uv sync --locked` и `.venv/bin/orca-slicer-mcp --help`. При установке для клиента используется постоянный путь инструмента, а не `.venv` рабочего дерева.

URL конечных точек и токены аутентификации не должны попадать в конфигурацию клиента или запросы агенту. Для специального `--datadir` Orca добавьте в `args` параметр `--directory` и абсолютный путь его каталога `cache/agent-control`.

## Включение Orca

Явно запустите специальную сборку. При обычном запуске API отключён.

```sh
ORCA_AGENT_CONTROL=1 \
ORCA_AGENT_INPUT_ROOTS='["/absolute/path/models"]' \
ORCA_AGENT_OUTPUT_ROOTS='["/absolute/path/exports"]' \
/Applications/OrcaSlicer.app/Contents/MacOS/OrcaSlicer
```

Корневые каталоги файлов задаёт владелец в виде JSON-массивов существующих абсолютных каталогов. Они настраиваются в окружении Orca, а не в аргументах инструментов. Без них файловые операции запрещены. Для нескольких процессов включите в Orca разрешение нескольких экземпляров. Обнаружение использует приватные дескрипторы в нативном каталоге данных. Закрытые и устаревшие конечные точки игнорируются; автоматического выбора другой цели нет.

В текущих сборках `ORCA_AGENT_CONTROL=1` также разрешает отправку заданий на печать и управление устройствами. Старым сборкам может дополнительно потребоваться `ORCA_AGENT_PRINTING=1` при запуске; проверяйте `transmission_enabled` в `printers.list`. Подготовка плана ничего не загружает на устройство.

## Инструменты и рабочий процесс

Исходные десять инструментов остаются доступны: `orca_list_instances`, `orca_get_capabilities`, `orca_get_scene`, `orca_get_settings_schema`, `orca_get_settings`, `orca_patch_settings`, `orca_start_slicing`, `orca_get_slice_result`, `orca_get_job`, `orca_cancel_job`.

Расширенные инструменты объединяют фиксированные разрешённые наборы нативных действий:

| Инструмент | Операции |
|---|---|
| `orca_files` | Импорт, открытие/сохранение 3MF, экспорт STL/3MF/G-code |
| `orca_plates` | Создание/выбор/переименование/дублирование/удаление/порядок/блокировка |
| `orca_instances` | Преобразования, перемещение на стол, центрирование/опускание, клонирование/удаление, ориентация, участие в печати |
| `orca_objects` | Клонирование, отделение, переименование, участие в печати, удаление, разделение, объединение в составной объект |
| `orca_parts` | Преобразования/разделение частей, примитивы модификаторов и их типы |
| `orca_arrange` | Нативная расстановка явно указанных экземпляров |
| `orca_geometry` | Проверка, разрез/соединители, булевы операции, упрощение, исправление |
| `orca_painting` | Грани поддержек/шва/материала, области, raycast и кисть |
| `orca_presets` | Список/описание/выбор/изменение/сохранение нового пользовательского пресета |
| `orca_preview` | Нативный PNG как изображение MCP |
| `orca_history` | Просмотр нативной истории, Undo/Redo |
| `orca_slice_plates` | Явный набор столов с последовательными дочерними заданиями |
| `orca_printers` | Состояние принтера/бэкенда, слоты AMS, внешние катушки и сопла |
| `orca_printer_selection` | Явный выбор на вкладке Device с синхронизацией сопла по умолчанию |
| `orca_printing` | Зафиксированные планы, отправка, сверка результата, управление устройством |
| `orca_recipes` | Обнаружение локальных рецептов, проверки, экспорт и наблюдение операций |
| `orca_recipe_library` | Неизменяемые ревизии, ответвления, архивирование и импорт через план |
| `orca_recipe_apply` | Планы композиции и однократное нативное применение |

1. Выберите полную пару UUID сессии/окна по намерению пользователя относительно проекта. При неоднозначности спросите; фокус, порт, PID и порядок списка никогда не выбирают цель.
2. Прочитайте возможности и сцену. `method_params_schemas` работающей сборки — авторитетная схема доменных `parameters`. Неподдерживаемые методы завершаются ошибкой без подмены автоматизацией UI или другим устройством.
3. Для изменений нужны актуальный `state_token` и уникальный `request_id`. В групповых инструментах токен находится внутри `parameters`. Настройки используют строки Orca (`"4"`, `"30%"`). Области процесса, стола, объекта, объёма и диапазона высот следуют нативной доступности ключей. Переопределения объекта затрагивают каждый экземпляр. Скрипты, учётные данные и сетевые настройки исключены из обычного изменения настроек/пресетов.
4. Обновляйте сцену после структурных изменений или Undo. Идентификаторы столов действуют в пределах эпохи документа. Геометрия/раскраска требуют ревизий сетки. Действуют нативные правила связанных экземпляров; при необходимости отделите копию. Геометрия поддерживает вычисляемый результат `preview:true` перед фиксацией.
5. Наблюдайте асинхронные задания через `orca_get_job`. Тайм-ауты и отмена MCP прекращают наблюдение, а не нативную операцию. Явно используйте `orca_cancel_job`. Нативные диалоги требуют ответа пользователя.
6. Нарезайте один текущий стол или явно заданный набор. Пакет заканчивается на последнем запрошенном столе и возвращает квитанции дочерних заданий; при сбое частичные квитанции сохраняются в деталях ошибки. Оценки являются прогнозами.

Конфликт требует повторного чтения и пересмотра изменения. Никогда не обновляйте токен ради автоматического повтора. Потеря ответа о приёме может означать, что операция выполнена: повторяйте только **точные исходные аргументы и ID запроса**. Когда известен ID задания, наблюдайте его. История запросов ограничена и не гарантирует выполнение ровно один раз навсегда. Для неизвестных методов используются консервативные рекомендации по повтору изменений.

## Выбор устройства и материала

Используйте `orca_printer_selection` с `printers.select`, явным бэкендом/устройством и токеном состояния сцены. Инструмент ждёт телеметрию и по умолчанию синхронизирует поддерживаемое единственное установленное сопло. Проверяйте `nozzle_sync.state`: `blocked` сообщает о проблеме профиля/телеметрии/компоновки, даже если устройство выбрано. Выбор общий для окон одного процесса Orca. После синхронизации сопла обновите состояние и выполните нарезку.

Читайте `printers.filaments` через `orca_printers` для слотов AMS/внешних материалов. Используйте сообщённые значения `tray_index`. `options.ams_mapping` задания — массив записей `{"filament_id": 2, "tray_index": 0}` с ID материалов проекта от 1, в точности покрывающий материалы завершённой нарезки. Неиспользуемые материалы проекта не блокируют печать. Поддерживается многоцветная AMS-печать с одним соплом; запуск с двумя соплами/стойкой сопел и многоцветная печать с ручной сменой катушки не проверены.

Необязательный [навык orca-mcp-control](../skills/orca-mcp-control/SKILL.md) содержит команды запуска и правило подтверждения владельцем: спрашивать непосредственно перед отправкой, кроме явно одобренного задания или выбранного принтера, имя которого содержит `virtual` без учёта регистра. Исключение не отменяет проверки совместимости и не доказывает, что далее не запустится физическое оборудование. Одного включения нативной переменной окружения недостаточно для одобрения отдельного задания. Английский `SKILL.md` остаётся единственным авторитетным исполняемым источником навыка.

## Печать

Явно указывайте бэкенд и устройство. `printing.prepare` фиксирует проверенную нарезку, конечную точку, параметры, хеш артефакта, входное состояние и срок действия. Подтверждайте ID предупреждений согласно схеме отправки. Используйте объявленный владельцем `endpoint_mode` (queue, direct, unknown), никогда не выводите его из имени. Даже операция только загрузки в очередь/виртуальную конечную точку может вызвать последующую печать.

Перед сетевым вводом-выводом отправка расходует долговечную межпроцессную заявку. Потеря ответа или сбой требуют сверки исходной операции; не отправляйте заново с новым ID. Нативный успех может означать принятие загрузки или задания и не доказывает физическую печать. Управление явно действует на всё устройство и затрагивает задание, которое конечная точка выполняет сейчас. Отмена локального рабочего потока не останавливает принтер.

Нативный каталог сообщает реальные ограничения бэкенда. Обычная загрузка PrintHost может быть доступна, когда запуск недоступен без проверенной телеметрии модели/сопла/материала. Не обходите ошибки нативной предпроверки.

## Проверка

Клиент проверяет приватные дескрипторы, соответствие UUID/файлов, точные loopback-адреса, отражённую цель, ограничения ответов и сроки. Прокси и перенаправления отключены; учётные данные скрываются. Проверка владельца и защищённых ACL Windows использует `pywin32` и отклоняет недоступные или неуспешные проверки.

```sh
uv run --locked python -m unittest discover -s tests -v
```

Тесты включают официальные stdio-сессии с независимыми аутентифицированными локальными фикстурами. Нативный GUI, реальные принтеры и выполнение в Windows/Linux требуют отдельных проверок; тесты адаптера их не подтверждают. См. [архитектуру](docs/architecture.ru.md) и [исторический журнал проверок](docs/verification.ru.md).

## Локальная библиотека рецептов (0.4.0)

Рецепты объединяют до 256 сериализованных настроек одной области. В одном плане можно соединить до 16 закреплённых ревизий и применить их одним нативным изменением настроек. Библиотека хранится в приватном SQLite, общем для MCP-клиентов; серверная служба или отдельное приложение не требуются.

- `orca_recipes`: описание схем действий, список/получение/проверка ревизий, экспорт переносимого JSON-дампа, наблюдение сохранённой операции применения.
- `orca_recipe_library`: создание/изменение/ответвление/архивирование рецептов; подготовка и фиксация импорта. Передавайте дамп исходным JSON-текстом, чтобы можно было отклонять повторяющиеся ключи.
- `orca_recipe_apply`: планирование композиции, проверка различий/предупреждений, однократное применение.

Начните с `orca_recipes(action="describe", parameters={"tool": "orca_recipe_apply", "action":"plan"})` для получения точных схем параметров. Зафиксируйте полную пару UUID окна, ID владельцев и текущий токен состояния. Создайте рецепты из явных значений, изучите `check`, затем закрепите ID/ревизию/хеш рецепта при планировании. Конфликтующие значения требуют явного разрешения. Применяйте точный хеш плана, подтверждайте его предупреждения и опрашивайте `operation.get` по квитанции. Никогда не повторяйте неопределённое применение: использованный план возвращает исходную операцию, в том числе после перезапуска MCP и с другим ID запроса.

В macOS база по умолчанию находится в `~/Library/Application Support/orca-slicer-mcp/recipes.sqlite3`. Переопределите её параметром **MCP-сервера** `--recipes-db /absolute/private/path/library.sqlite3`; укажите одинаковый путь в клиентах, которым нужна общая библиотека. Это не аргумент запуска Orca. Хранилище создаётся автоматически; более новые неподдерживаемые версии запрещены. Семантическая миграция рецептов требует явных поддерживаемых правил; v1 не придумывает замены изменившимся настройкам Orca.

См. [контракт v1](docs/contracts/recipes-v1/CONTRACT.ru.md) об ограничениях, переносимости, совместимости и долговечности. Заявленную совместимость материала/модели пока нельзя установить через нативный API, поэтому она блокирует применение; диаметр сопла и скалярную высоту слоя можно проверить. Пустые ограничения не подтверждают физическое качество печати. Процессы из нескольких команд не входят в v1.
